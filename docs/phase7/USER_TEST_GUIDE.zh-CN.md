# 不编程用户的最少测试步骤

这是默认关闭的实验适配，不是完整物理恢复版。原版研究尚未给出可直接接入所有材料的 Level 生产者，因此“站进流沙就自动恢复原版行动限制”本轮没有开启。下列命令显式注入测试输入。

1. 用 Java17 / Minecraft1.20.1 / Forge47.2.0，在隔离测试实例加载本分支构建的模组。不要替换日常存档的模组直接试验。先复制整个测试世界目录作备份。
2. 新建一次性世界，名称以 `MFQM_PHASE7_` 开头，例如 `MFQM_PHASE7_TEST`。开启作弊。首次进入后退出游戏/关闭服务器，编辑该世界的 `serverconfig/mfqm-server.toml`。
3. 设置 `[phase7]` 下 `testWorld=true`、`stuckLease=true`；需要诊断日志时才设 `diagnostics=true`。其他配置不变。重新打开世界。
4. 在安全平台上切换生存模式，先用 `/mfqm_phase7 hold 145 100` 测试约5秒行动属性限制，再用 `/mfqm_phase7 release` 立即释放。创造/旁观/无敌和骑乘免疫，新开关不会覆盖这些模式。`contact 145` 只排队一次输入，持续约一帧，适合日志观察。
5. 在浅/深流沙中重复 hold/release，比较行动属性；这仍是手工注入 Level，不能把它记录成材料深度公式已经恢复。hold 每次 Update 前提交同一值，最多200tick；不会永久留下属性。
6. Dry 会改动方块。只在备份过的一次性区域，站在已加载区块内选择明确坐标，例如 `/mfqm_phase7 dry 0 80 0 5 0`（坐标、旧循环范围extent、seed）。范围只允许-1..18；未加载区块/超出高度会拒绝。它不是完整 Surface，也不会自动生成遍布世界。
7. 看日志中的 PHASE7_STUCK/PHASE7_DRY 条目（diagnostics=true时）。原材质未公开打包，当前依然引用 Minecraft 原版贴图，不能与旧 MFQM 原图混称。
8. 回滚：先 `/mfqm_phase7 release`；关闭游戏/服务器，把两个开关改回false并重启。Dry 已写入的方块不会自动撤销；恢复备份可撤销测试区域。测试报告附上版本、开关、种子、命令、场景和原始日志。

已知：新属性可能改变 FOV，客户端属性同步的过渡帧尚未实测；不要依赖本轮完成跳跃空气控制、完整净Y下沉或其他模组兼容。看到异常可直接停止实验并恢复备份，无需继续正式存档测试。
