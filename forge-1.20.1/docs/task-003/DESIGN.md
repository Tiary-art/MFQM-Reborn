# Task 003 implementation contract

Baseline: f9a6fc7 (latest main, Task 002 merged). Versions and dev_test_block remain unchanged. All new behavior is an approximation based on static evidence; there is no recorded 1.7.10 trajectory baseline.

- Stable IDs: mfqm:quicksand, mfqm:mud, mfqm:soft_quicksand. Public models reference Minecraft sand/mud/red_sand; no old PNG/audio.
- Server LevelTick END visits each living entity once. A per-capability level-time guard prevents duplicate settlement; blocks never apply physics, damage, or oxygen. Eye coverage is independently sampled.
- Modern depth = material surface minus entity feet, normalized by current entity height. No legacy player Y offset, onGround spoof, web flag, or client physics solver. Velocity packets plus vanilla movement-attribute sync carry server decisions; custom snapshots are read-only on clients. Real-client testing showed velocity packets alone do not constrain player position batches: the server now bounds each active player's displacement against its previous accepted position, last vertical decision and composed speed attribute, using vanilla position correction. This may visibly correct a delayed client; it is a bounded approximation, not a recovered legacy trajectory or a general anti-cheat. Forge teleports clear contact/history, and unknown jumps over16 blocks bypass correction. Direct teleports below16 blocks by other mods remain an integration risk.
- Quicksand: zero horizontal momentum, depth-dependent buoyancy minus gravity, movement/struggle suction. SoftQuicksand: 0.71 base drag, separate buoyancy and deep center pull. Mud: exact discrete pool-neighbor decisions and 0.7/0.5/0.25/empty collision shapes; bounded modern motion coefficients. Numerical equality is not claimed.
- A capability separates transient contact/stuck/air/input/tick guard from versioned persistent mud residue (no visual cover). Only our transient speed modifier UUID is modified. Normal exit recovers air; death, respawn, dimension changes, logout/removal clear transient state/modifier/input. NBT never stores active/stuck/air or a packed signed integer.
- Forge invalidation permanently invalidates existing LazyOptional handles. Since a ServerPlayer is reused on dimension transfer, a subsequent query through Forge's revived outer dispatcher creates a new handle for the same cleaned state. Old handles stay invalid. An actual-client dimension test exposed the missing re-creation; an additional GameTest covers invalidation/revival/re-entry separately from synthetic dimension events.
- Oxygen default300, -1/tick when eyes covered, +5 outside, one damage request per16 ticks after depletion; damage=max(maxHealth*0.1,2)*multiplier. Separate player/mob oxygen toggles; disabling the oxygen reservoir retains eye-cover damage on a16tick clock (explicit difference from legacy per-collision calls).
- Creative/spectator/invulnerable entities do not sink or lose custom air. All solver inputs/output are finite-clamped; no changes to unrelated modifiers or vanilla water-air state.
- C2S only boolean struggle intent, rate-limited and only accepted near active material; no client position/velocity/depth accepted. S2C validated dimension/entity UUID/timestamp snapshots; periodic retry handles tracking spawn order. Small HUD/debug trace tools, no large effects or rescue/worldgen systems.
- Automated tests: pure JUnit model/geometry/boundaries; live Forge GameTests including foundation regression, real drops, geometry, mixed-cell once/tick, air/damage/exit, lifecycle/NBT/modifier cleanup. Actual client/singleplayer and local dedicated connection are distinct acceptance rows; missing cases stay unverified.
